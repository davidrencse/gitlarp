# Repository workbench

Scope: Operate. A developer connects GitHub, selects a repository, reviews concrete improvements, and publishes a branch. Seed c2aa424e assigned candidate 6; its material expression is constrained by the user's subsequently pinned simple black UI.

Grounded candidates: code review split view; project library; package registry; release checklist; commit graph explorer; software release workbench; documentation editor. Candidate 6 combines a repository library with a linear review-and-publish workbench.

## WORLD
Black developer workspace with restrained violet controls, low-chroma surfaces, self-hosted DM Sans and Sora, consistent 1px borders, Lucide icons, compact navigation and spacious working content. Sora replaced the provisional Space Grotesk after the mechanical detector flagged its overuse.

## FIRST VIEWPORT
A 224px sidebar, utility header, project introduction and a wide repository-to-documentation commit graph banner. Search and filters sit directly above a three-column repository library. Repository names, descriptions, language, stars, and observed readiness are immediately readable. Demo identity and data are explicitly labeled.

## VISITOR PATH
Browse projects, inspect actual evidence, choose modules, review editable files and meaningful commit groups, choose branch/fork/new documentation repository, and publish. Navigation supports documents, history, activity, and connection settings.

## SIGNATURE INTERACTION
The release stepper advances only when real work resolves. Selecting a repository opens its workbench. Generating reveals a navigable file tree and Markdown/code preview; edits are reflected in downloaded and published files. Publishing shows the actual result or an actionable error.

## CROSS-SURFACE REACH
Same sidebar, surface tokens, control vocabulary and native focus states carry through the library, editor, activity log, settings and mobile stacked workbench.
